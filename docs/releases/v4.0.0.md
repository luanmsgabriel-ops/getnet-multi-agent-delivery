# v4.0.0 (2026-11-19)

The v4 round answers the v3 evaluation, point by point. Every change was decided by the author before it was built (`docs/DECISIONS.md`) and measured with the real model. The numbers below are from the final regression and the load test. Results that missed their targets are reported as measured.

## Highlights
- **Under load:** 10 concurrent merchants. p95 27.3 s per turn, 100% availability, US$ 0.026 per turn. SLOs and burn-rate alerts are tested with `promtool`.
- **Quality:** the 10 challenge questions × 3 pass 100% (judge 100%). The frozen 60-question holdout passes 98% (judge 97%).
- **Judge:** calibrated against two independent human raters (kappa 0.85, AC1 0.98).
- **Answer verifier:** Claude Haiku checks figures, dates and merchant data before an answer leaves.
- **Human in the loop:** operator console, Telegram channel with replies, deadlines, audit trail. The operator's text is screened too.
- **Two-phase actions:** anticipation of receivables and terminal service. The model proposes; only the merchant confirms, idempotent and audited.
- **Production state and identity:** Postgres for state, Redis for shared rate limits, OIDC tokens checked against JWKS.
- **Security evidence:**
  - public attack sets: 90.6% blocked, 0% false positives;
  - indirect injection at scale: 0/20 obeyed;
  - multi-turn attacks: 0/6 failed;
  - memory poisoning: 0 values stored.

## Targets not met
- Retrieval recall@5: 0.73 on the frozen holdout (target 0.8).
- Public attack sets: 90.6% blocked (target 95%).
- First specialist at work: p95 7.9 s under load (target 5 s).

## Upgrade notes
- `docker compose up` now also starts Postgres, Redis and a development OIDC provider. Run `make setup` again on a fresh clone for `POSTGRES_PASSWORD`.
- Tokens come from the OIDC provider (`make token`). Local HS256 tokens work only outside compose.
- New merchant scope `actions:write` for confirming actions.
- New settings, all optional:
  - `OIDC_ISSUER`, `OIDC_AUDIENCE`
  - `STATE_DATABASE_URL`, `REDIS_URL`
  - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OPERATOR_CHAT_IDS`
  - `REPLAN_DEADLINE_S`, `VERIFY_ANSWERS`
